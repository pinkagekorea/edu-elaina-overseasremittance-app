# 데이터에 물어보기 (elaina-ask) — 설계

작성 2026-08-14

## 왜

직원이 폰에서 「7월 JH 송금액」 한 줄을 던지면 숫자가 나와야 한다. 지금은
대시보드를 열고, 월별 상세 내역을 좌우로 밀고, 거래처 줄을 눈으로 찾아야 한다.

물어보는 곳은 하나면 되고, 답은 숫자 하나면 된다. 대신 **그 숫자가 어디서
왔는지**가 늘 붙어야 하고, **없는 것은 없다고** 해야 한다.

## 지켜야 하는 네 가지

| # | 규칙 | 어떻게 지키나 |
|---|---|---|
| 1 | 읽기전용·조회만 | Edge 함수 코드에 `insert·update·delete·upsert·rpc` 가 **없다**. `.select()` 만 있다 |
| 2 | 출처 표시 | 답 JSON 에 `source{table,rows,filters}` 가 항상 들어간다. 숫자만 나가는 경로가 없다 |
| 3 | 지어내지 않음 | 값은 조회 결과에서만 만들어진다. 못 알아들으면 `unparsed`, 줄이 없으면 `none` |
| 4 | 8일차 화면 권한 | 직원의 JWT 로 붙어 RLS 가 판정 + 표 화이트리스트 |

**프롬프트로 부탁하지 않고 코드 모양으로 지킨다.** 규칙을 말로 적어 두면
지켜지는지 확인할 방법이 없다. 부를 함수가 없으면 확인할 필요도 없다.

## 정한 것과 그 이유

**API 키를 쓰지 않는다.** `ANTHROPIC_API_KEY` 가 없어서 규칙 기반 파서로
간다. 이 도메인은 좁다 — 표 4개, 거래처 7곳, 항목 10개, 기간 몇 가지.
규칙으로 덮인다. 그리고 **못 알아들으면 확실히 못 알아듣는다**는 점이
규칙 (3)에 더 맞는다. 모델은 그럴듯한 답을 만들 수 있지만 파서는 못 한다.

나중에 키가 생기면 `parse.ts` 만 갈아끼운다. `index.ts` 는 그대로다.

**service_role 을 쓰지 않는다.** 기존 `elaina-slack-relay` 는 service_role 로
붙어 스스로 권한을 따진다 — 알림은 남의 줄도 읽어야 해서 그게 맞다.
여기서는 틀리다. service_role 은 RLS 를 통째로 건너뛴다. anon 열쇠에 직원의
JWT 를 실으면 판정을 Postgres 가 한다. 코드가 실수해도 권한은 안 뚫린다.

**RLS 위에 화이트리스트를 한 겹 더 겹친다.** `edu` 스키마에는
`luka_returns` 처럼 `USING (true)` 로 열린 표가 있다. RLS 하나만 믿으면
8일차 직원이 루카 반품 5,606행을 조회하게 된다. 볼 수 있는 표를 서버에
적어 둔다 — 화면에 두면 화면을 고쳐 우회할 수 있다.

**DB 를 바꾸지 않는다.** 새 표도 새 함수도 만들지 않는다. 기존 RLS 와
PostgREST 만 쓴다. 마이그레이션이 없으면 되돌릴 것도 없다.

**기간을 지어내지 않는다.** 「JH 송금액」처럼 언제인지 없으면 오늘 날짜로
채우지 않고 되묻는다. 기간을 채우면 틀린 달의 숫자가 맞는 척 나간다.
거래처와 항목은 다르다 — 빠지면 각각 「그 달 전체」·「실제 송금액」으로
보되, **그렇게 봤다고 답에 적는다**. 조건이 눈에 보이면 틀린 걸 알아챌 수 있다.

**「7월」의 연도는 자료에서 고른다.** 올해를 붙이면 자료에 없는 달을 물어본
셈이 된다. 그 달이 실제로 있는 해 중 가장 나중 것을 쓴다.

## 조각

| 조각 | 자리 | 하는 일 |
|---|---|---|
| `parse.ts` | `supabase/functions/elaina-ask/` | 말 → 기간·항목·거래처·표. DB 도 네트워크도 모른다 |
| `index.ts` | 같은 곳 | 인증 · RLS 클라이언트 · `.select()` · 답 만들기 |
| `Ask` 모듈 | `index.html` | 물어보고 받아 적기. 표 이름도 규칙도 비밀값도 없다 |

`parse.ts` 가 순수해서 따로 시험할 수 있다. 이것이 나눈 이유다.

## 볼 수 있는 표

```
edu_elaina_overseasremittance   월·거래처별 송금 실적   (기본)
elaina_monthly_baseline         위의 기준선            ("기준선" 이라고 하면)
elaina_daily_reports            날짜별 리포트 숫자      ("리포트"·날짜를 대면)
elaina_remittances              건별 송금              ("건별"·"사유"·"예정일")
```

여기 없는 이름은 어떤 질문으로도 닿지 않는다.

## 말 → 조건

**기간** — `2026-08-12` · `2026-08` · `2026년 7월` · `7월` · `지난달` ·
`이번 달` · `오늘` · `어제`. 못 뽑으면 되묻는다.

**항목** — 순서가 규칙이다. 긴 말이 먼저 온다.

- `건수`가 맨 앞 — 「미송금 건수」를 미송금으로 읽으면 안 된다
- `미송금`이 `송금`보다 앞 — 뒤에 두면 미송금이 송금으로 읽힌다
- `미송금`은 원화 칸이 없어 달러·위안 두 줄로 답한다

**거래처** — 표에 실제로 있는 이름하고만 맞춘다. 두 번 본다: 이름 전체,
그다음 토막(`스타위그-스퀘어` → `스타위그`·`스퀘어`). **둘 이상 걸리면
고르지 않고 되묻는다** — 아무거나 고르면 틀린 거래처의 숫자가 맞는 척 나간다.

**남은 말** — 기간·항목으로 설명되지 않은 말이 남았는데 거래처를 못 찾았으면
「‘XYZ’ 를 거래처에서 찾지 못했습니다」로 답한다. 그 달 전체 합계를 주면
「7월 없는거래처 송금액」이 그 달 총액으로 답한다.

## 답

```
2026-07 · JH · 실제 송금액
24,601,648원

출처 edu.edu_elaina_overseasremittance · 1줄
조건 remit_month = 2026-07 · vendor_name = JH
```

| 갈래 | 언제 | 화면 |
|---|---|---|
| `ok` | 줄이 있고 칸에 값이 있음 | 숫자 + 출처 (+ 가정한 것) |
| `none` | 줄이 0 · 칸이 빔 · 거래처 못 찾음 | 「데이터 없음」 + 무엇으로 찾았는지 + 있는 달·거래처 |
| `unparsed` | 기간이 없음 · 거래처가 모호 | 되묻기 + 예시 |
| `denied` | RLS 가 막음 | 「볼 권한이 없습니다」 |

`none` 과 `unparsed` 는 오류가 아니라 답이다. 붉게 칠하지 않는다.

## 확인한 것

`parse.ts` 를 26가지로 시험했다 (붙여 쓴 말, 줄여 부른 거래처, 모호한
거래처, 없는 거래처, 자료에 없는 달, 합계가 0 을 지어내지 않는지).

Edge 가 던질 질의를 SQL 로 재현해 숫자를 맞춰 봤다:

| 질문 | 조건 | 줄 | 값 |
|---|---|---|---|
| 7월 JH 송금액 | `remit_month=2026-07, vendor_name=JH` | 1 | 24,601,648원 |
| 지난달 미통관 | `remit_month=2026-07` | 3 | 63,109,284원 |
| 8월 성창 건수 | `remit_month=2026-08, vendor_name=성창` | 1 | 1건 |
| 12월 JH 송금액 | `remit_month=2026-12, vendor_name=JH` | 0 | 데이터 없음 |

**아직 확인하지 못한 것** — 배포된 Edge 함수 자체. 이 기계에 deno·supabase
CLI 가 없어 타입검사도 로컬 실행도 못 했다. 배포한 뒤 폰에서 한 번 눌러
봐야 한다.

## 일부러 안 하는 것

차트 · 대화 이어가기 · 질문 기록 저장 · 여러 달 비교 · 다른 팀 표.
전부 「한 줄 묻고 숫자 하나」를 깬다.

## 알려진 한계

- 매출·주문 표가 DB 에 없다. 「지난주 A채널 매출」류는 답할 수 없다
- `elaina_remittances` 는 0행이라 「건별」 질문은 당분간 전부 데이터 없음
- 한 번에 한 달만 본다. 「1월부터 7월까지」는 못 읽는다
- 500줄까지만 읽는다. 넘으면 답에 그 사실을 적는다
