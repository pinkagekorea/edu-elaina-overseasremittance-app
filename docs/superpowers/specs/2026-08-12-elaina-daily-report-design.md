# 데일리 리포트 (elaina) — 설계

작성 2026-08-12

## 왜

매일 아침 확인하는 숫자는 딱 둘이다 — **실제 송금액(원)** 과 **미통관 금액(원)**.
지금은 「월별 상세 내역」의 9열 표를 좌우로 밀어 가며 두 칸을 찾아 읽고, 전달
줄을 눈으로 되짚어 비교한다. 매일 하는 일이라 매일 같은 모양이어야 한다.

그래서 두 숫자만, 전달과 나란히, 표 하나로 고정한다. 해석은 넣지 않는다 —
증감은 화살표와 색으로 보이고, 무슨 뜻인지는 보는 사람이 안다.

## 무엇을 만드나

| 조각 | 위치 |
|---|---|
| 표 `edu.elaina_daily_reports` | `..._elaina_daily_report_table_and_rls.sql` |
| 생성 함수 `elaina_build_daily_report` | `..._elaina_daily_report_function.sql` |
| 매일 09:00 cron | `..._elaina_daily_report_cron.sql` |
| 카드 + `Report` 모듈 | `index.html` |

## 정한 것과 그 이유

**"이번 달" 은 달력 기준이다.** 리포트 날짜가 속한 달이 이번 달, 그 한 달 전이
전달. 데이터에 있는 최신 달을 쓰면 입력이 늦어질 때 며칠 내내 같은 달이 반복돼
"매일 같은 모양" 이 깨진다. 달력 기준이면 8월 행이 아직 없어도 `0` 으로 나오고,
행이 들어오는 순간 숫자가 붙는다 — 그것 자체가 정보다.

**화면은 원본을 다시 집계하지 않는다.** 아침 9시에 한 번 계산해 스냅샷 한 줄로
쌓고, 화면은 그 줄만 읽는다. 과거 날짜를 고르면 *그날 아침의 숫자* 가 그대로
나온다. 원본을 다시 더하면 과거를 고르는 의미가 없어진다 (지금 값이 나올 테니).

**증감은 저장하지 않는다.** 네 숫자만 저장하고 뺄셈은 화면에서 한다. 저장된 차이와
보이는 차이가 어긋날 자리를 아예 만들지 않는다.

**AI 를 쓰지 않는다.** 합계·뺄셈·나눗셈뿐이다. 문장은 고정된 제목과 열 이름만 있고,
숫자를 말로 옮기는 자리는 없다.

**cron 은 pg_cron 이다.** `pg_cron` 이 이미 설치돼 있고, DB 안에서 도니까 브라우저·
네트파이·외부 열쇠가 필요 없다. `0 0 * * *` = 00:00 UTC = **한국 09:00**. 한국은
서머타임이 없어 연중 고정이다.

**읽기 권한은 원본과 같은 규칙을 쓴다.** 원본 표
`edu_elaina_overseasremittance` 의 읽기 정책이 `@pinkage.co.kr` 이메일이므로,
그 요약인 이 표도 같은 줄을 쓴다. 요약이 원본보다 넓게 보이면 안 된다.

## 표

```
edu.elaina_daily_reports
  report_date    date primary key   -- 한국시간 기준 날짜
  generated_at   timestamptz        -- 실제 만들어진 시각 (제목 옆에 찍힘)
  cur_month      text               -- '2026-08'
  prev_month     text               -- '2026-07'
  cur_paid_krw   numeric   prev_paid_krw   numeric
  cur_uncl_krw   numeric   prev_uncl_krw   numeric
  status         text               -- 'ok' | 'error'
  error_text     text
```

## 잠금

- `authenticated` 에 **SELECT 만** 준다. insert/update/delete 권한이 없으므로
  화면에서는 쓰기가 문법적으로 불가능하다 — RLS 판정 전에 Postgres 가 막는다.
  쓰는 것은 `SECURITY DEFINER` 인 생성 함수뿐이다.
- 정책 하나: `lower(auth.jwt()->>'email') like '%@pinkage.co.kr'`.
- 생성 함수는 `revoke ... from public, anon, authenticated` — cron(postgres) 만 부른다.
- `anon` 은 표·함수 전부 권한 0.

## 실패

생성 함수 안을 `exception` 으로 감싼다. 무엇이 터지든 그 자리에서
`status='error'`, `error_text=SQLERRM` 로 한 줄을 남긴다 — **실패도 리포트다.**
줄이 없는 것과 줄이 error 인 것은 다른 사고이고, 화면은 셋을 구분해 보여준다.

| 상황 | 화면 |
|---|---|
| `status='error'` | `2026-08-12 09:00 생성 실패 · <사유>` |
| 오늘 줄이 아예 없음 (cron 이 안 돎) | `오늘 09:00 리포트가 없습니다 · 마지막 생성 2026-08-11 09:00` |
| 조회 자체 실패 (네트워크·권한) | 카드 안 오류 문구 + 다시 시도 버튼 |

전체 화면을 덮는 기존 `showError` 는 쓰지 않는다. 리포트가 실패해도 월별 상세
내역·차트는 멀쩡하므로 카드 안에서만 알린다.

## 화면 — 별도 화면 (2026-08-13 변경)

처음에는 대시보드 맨 위 카드였으나 별도 화면으로 옮겼다. 제목 「해외송금
현황」 아래 네이비 버튼 두 개(**데일리 리포트** · **주간회의**)로 들어가고,
주소는 `?view=daily` 다. 화면 왼쪽 위 `← 대시보드` 로 돌아온다.

주소·뒤로가기는 `Nav` 모듈 한 곳에서 맞춘다 — 화면마다 따로 맞추면 서로
어긋난다. 화면을 열 때마다 다시 읽는다. 어제 받아 둔 숫자를 오늘 보여주지
않기 위해서다.

```
데일리 리포트        2026-08-13 09:00 생성      [ 2026-08-13 ▾ ]

이번 달 · 전달
달력 기준 누계끼리 · 이번 달은 아직 쌓이는 중입니다
항목              이번 달 (2026-08)   전달 (2026-07)          증감
실제 송금액(원)       102,956,516      125,705,822   ▼ 22,749,306 (18.1%)
미통관 금액(원)       102,956,516       63,109,284   ▲ 39,847,232 (63.1%)

당일 · 전날
하루 사이에 움직인 만큼 (2026-08-12 → 2026-08-13)
항목             당일 (2026-08-13)  전날 (2026-08-12)         증감
실제 송금액(원)       102,956,516       98,000,000   ▲  4,956,516  (5.1%)
미통관 금액(원)       102,956,516      110,000,000   ▼  7,043,484  (6.4%)
```

- 표 둘. 보는 숫자 둘도, 열 넷도, 증감 규칙도 두 표가 같다 — 견주는 상대만
  다르다 (달 ↔ 날). 요약 문장·해석 문장은 여전히 없다.
- 증가 빨강 `--delta-up`, 감소 파랑 `--delta-down`, 변화 없으면 색 없이 `–`.
  기존 `--up`(초록)·`--down`(빨강)은 앱 전체에서 *좋음/나쁨* 으로 쓰이고 있어
  재사용하지 않는다. 여기 색은 좋고 나쁨이 아니라 방향이다.
- 전달이 0 이면 % 는 `–` (0 으로 나누지 않는다). 금액 차이는 그대로 보여준다.
- `▾` 는 스냅샷이 있는 날짜만 담는다 (최근 30일). 고르면 그 줄로 갈아끼운다.

### 당일·전날 표 (2026-08-13 추가)

**같은 자리를 하루 사이로 견준다.** 두 스냅샷의 `cur_*` 끼리 뺀다. 둘 다 「이번
달 누계」이므로 그 차이가 곧 *그 하루 동안 늘어난 만큼* 이다. 여기서도 원본을
다시 집계하지 않는다 — 스냅샷 둘만 있으면 되는 뺄셈이다.

**앞 스냅샷은 「달력상 전날」이 아니라 「목록에서 바로 앞줄」이다.** 하루가 비면
`직전 (2026-08-01)` 로 열 이름을 바꾸고, 비었다는 사실을 표 위에 적는다. 없는
날을 있는 척 채우지 않는다.

| 상황 | 화면 |
|---|---|
| 앞줄이 없음 (가장 오래된 리포트) | `견줄 앞 리포트가 없습니다 …` — 표를 그리지 않는다 |
| 앞줄이 `status='error'` | `2026-08-11 리포트가 생성에 실패해 견줄 수 없습니다.` |
| 하루가 빔 | 열 이름 `직전 (날짜)` + `2026-08-08 리포트가 없어 … 견줍니다` |
| 달이 바뀜 | 두 값은 보여주되 증감은 `–` |

**달이 바뀌면 빼지 않는다.** 누계가 1일에 0 부터 다시 시작하므로, 빼면 한 달치가
통째로 줄어든 것처럼 보인다. 그것은 사실이 아니다. 그래서 증감 칸을 `–` 로 두고
"달이 바뀌어 누계가 새로 시작한다" 를 표 위에 적는다.

## 일부러 안 하는 것

해석 문장 · 슬랙 알림 · 차트 · USD/CNY 열 · 수동 생성 버튼 · 거래처별 쪼개기.
전부 「월별 상세 내역」에 이미 있거나, "표 하나로 끝" 을 깬다.

## 알려진 한계

- 스냅샷은 앞으로 쌓인다. 오늘 이전 날짜는 고를 수 없다 (그날의 숫자를 아무도
  기록해 두지 않았으므로 지어낼 수 없다).
- 원본 행이 나중에 수정돼도 지난 스냅샷은 바뀌지 않는다. 그게 스냅샷의 뜻이다.
- 09:00 은 UTC 고정이다. 한국 밖에서 쓰게 되면 cron 식을 다시 정해야 한다.
